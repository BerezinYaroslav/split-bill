# PayTogether MVP

Telegram-бот для разделения ресторанного чека по фотографии.

## Что умеет бот

- принимает фото чека в Telegram;
- сразу отвечает, что фото принято и обрабатывается;
- по умолчанию распознаёт чек через OpenAI Vision API;
- после распознавания сверяет итог по позициям с суммой в чеке и, если суммы не сходятся, делает повторную попытку распознавания;
- скрывает позиции с нулевой стоимостью;
- выводит итоги чека на русском языке: `Промежуточный итог`, `Сервисный сбор`, `Итого`;
- после каждого нового фото заново запрашивает список участников;
- принимает участников обычным текстовым сообщением, а не через `/people`;
- проводит пользователя по позициям по одной, а не показывает все блюда сразу;
- позволяет для каждой позиции выбрать конкретных участников или разделить позицию на всех;
- после распределения позиций спрашивает про чаевые;
- если чаевые нужны, просит ввести сумму и затем выбрать, делить их на всех или на конкретных участников;
- считает итоговую сумму по каждому человеку с учётом блюд, сервисного сбора и чаевых.
- если у пользователя ещё нет текста обратной связи, бот предлагает её оставить после 1, 3, 5 и 10 успешного подтверждённого расчёта;
- может сохранять эту обратную связь в Google Sheets отдельной строкой.

## Текущий UX flow

1. Пользователь отправляет фото чека.
2. Бот пишет: `Фото получено, обрабатываю чек. Пожалуйста, подожди.`
3. Бот показывает распознанные позиции и суммы чека.
4. Бот просит прислать участников обычным сообщением:

```text
Ярослав, Лера, Ксюша
```

5. Бот показывает позицию `1 из N`.
6. Пользователь отмечает, кто ел эту позицию, или нажимает `Поделить на всех`.
7. Пользователь нажимает `Дальше`, и бот переходит к следующей позиции.
8. После последней позиции бот спрашивает, добавить ли чаевые.
9. Если чаевые нужны, бот:
   - просит прислать сумму;
   - затем предлагает:
     - `Разделить на всех`;
     - или выбрать конкретных участников и нажать `Готово`.
10. Бот отправляет финальный split.
11. Если в Google Sheets у пользователя пустой `feedback_text`, бот предлагает оставить отзыв после 1, 3, 5 и 10 успешного подтверждённого расчёта.
12. Текст обратной связи сохраняется в Google Sheets, если интеграция настроена.

## Команды

- `/start` — сбросить текущую сессию и начать заново;
- `/donat` — получить ссылку для финансовой поддержки команды;
- `/summary` — показать текущий итоговый split;
- `/reset` — очистить текущую сессию.

## Структура проекта

- `main.py` — точка входа;
- `paytogether/bot.py` — Telegram flow и сценарии пользователя;
- `paytogether/ai_extractor.py` — распознавание чека через OpenAI Vision API;
- `paytogether/parser.py` — форматирование и вспомогательная логика чека;
- `paytogether/splitter.py` — расчёт долей по позициям и чаевым;
- `paytogether/state.py` — in-memory состояние Telegram-сессии;
- `tests/` — базовые тесты парсинга и распределения сумм.

## Сбор обратной связи в Google Sheets

Чтобы после первого разделённого чека сохранять ОС в таблицу, нужно:

1. Создать Google Cloud project.
2. Включить Google Sheets API.
3. Создать Service Account.
4. Скачать JSON-ключ сервисного аккаунта.
5. Открыть нужную Google Sheet и дать сервисному аккаунту доступ `Editor`.
6. Создать в таблице лист, например `feedback`.

Переменные окружения:

```bash
export GOOGLE_SHEETS_SPREADSHEET_ID=...
export GOOGLE_SHEETS_WORKSHEET_NAME=feedback
export GOOGLE_SERVICE_ACCOUNT_FILE=/absolute/path/to/service-account.json
```

Вместо файла можно передать JSON целиком:

```bash
export GOOGLE_SERVICE_ACCOUNT_JSON='{"type":"service_account",...}'
```

В Google Sheets бот добавляет строку со столбцами:

- `timestamp_utc`
- `chat_id`
- `user_id`
- `username`
- `full_name`
- `feedback_text`

## Распознавание чека

Основной путь:

- OpenAI Responses API;
- image input;
- ответ в JSON, который сразу маппится в модель чека.

OpenAI docs, на которые опирается интеграция:

- [Responses API](https://platform.openai.com/docs/api-reference/responses/retrieve)
- [Images and vision](https://platform.openai.com/docs/guides/images-vision)

### Повторное распознавание при расхождении сумм

После первичного распознавания бот сравнивает:

- сумму всех позиций с учётом скидок;
- `Промежуточный итог`;
- `Итого`.

Если суммы заметно расходятся, бот делает повторную попытку распознавания с усиленной подсказкой про возможную потерю тысячных разрядов, например:

- `256` вместо `1 256`;
- `290` вместо `1 290`;
- `110` вместо `1 110`.

## Отладка и типовые проблемы

### Telegram долго отдаёт фото

Если в логах есть `telegram.error.TimedOut` на шаге `get_file`, это сетевой таймаут между ботом и Telegram, а не ошибка OpenAI.

Что помогает:

- отправить фото как обычное изображение, а не слишком большой файл;
- повторить отправку через несколько секунд;
- проверить локальное соединение, VPN и firewall.

### OpenAI возвращает 401

Это означает, что `OPENAI_API_KEY` неверный или недействительный. Проверь ключ и заново экспортируй переменную окружения.

### OpenAI недоступен

Если OpenAI API не отвечает, ключ неверный или `OPENAI_API_KEY` не задан, бот не будет использовать локальный OCR. Вместо этого он явно сообщит, что распознавание сейчас недоступно.

### Посмотреть сырое распознавание

Для диагностики отправь команду:

```bash
/ocr
```

## Ограничения текущей версии

- состояние хранится в памяти процесса;
- без БД и без вебхуков;
- качество распознавания всё ещё зависит от качества фотографии;
- без доступного OpenAI API бот не сможет распознать чек;
- чаевые распределяются равномерно между выбранными участниками;
- редкие нестандартные форматы чеков всё ещё могут требовать дополнительной настройки prompt и валидации ответа.

## Безопасность

- не публикуй `TELEGRAM_BOT_TOKEN`;
- не публикуй `OPENAI_API_KEY`;
- если токен или ключ попал в логи/чат, перевыпусти его.
