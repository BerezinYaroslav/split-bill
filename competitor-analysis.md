# Анализ конкурентов PayTogether

Дата среза: 18 марта 2026

## Что такое PayTogether сейчас

По README текущий продукт PayTogether это Telegram-бот для сценария:

- пользователь отправляет фото ресторанного чека;
- бот распознает позиции через OpenAI Vision;
- пользователь распределяет блюда по людям поштучно;
- бот считает сервисный сбор и чаевые;
- бот выдает итог по каждому человеку.

Сильная сторона продукта уже сейчас: очень короткий путь от бумажного чека до готового персонального расчета, без установки отдельного приложения.

## Кого сравнивали

Прямые и косвенные конкуренты:

1. Splitwise
2. Split-it
3. Spliit
4. Tricount
5. Settle Up
6. Splid
7. Ручной подсчет калькулятором / заметками

## Ключевые выводы

1. Прямой рынок делится на две большие группы:
   - broad expense trackers для жизни, поездок и дома;
   - receipt-first bill split продукты для ресторанов и разовых встреч.
2. PayTogether сильнее второй группы по низкому порогу входа, потому что Telegram уже установлен и сценарий начинается с фото.
3. PayTogether пока слабее первой группы по "долгой ценности":
   - нет постоянных групп;
   - нет истории долгов и погашений;
   - нет мультивалютности;
   - нет экспорта;
   - нет recurring expenses;
   - нет совместного live-редактирования;
   - нет payment rails и reminders.
4. Наиболее опасные конкуренты по продуктовой логике:
   - Splitwise как market standard;
   - Spliit как free/open alternative;
   - Settle Up и Tricount как зрелые long-term trackers.
5. Наиболее опасный "невидимый" конкурент:
   - ручной подсчет, потому что в ресторане люди не всегда готовы ставить новое приложение.

## Где PayTogether уже выигрывает

- Telegram-формат снимает барьер установки отдельного приложения.
- Фото чека это естественная точка входа.
- По-item распределение блюд уже встроено в основной флоу.
- Есть отдельная логика для сервисного сбора и чаевых.
- Русскоязычный UX уже готов.
- Есть цикл обратной связи через Google Sheets.

## Где PayTogether проигрывает сегодня

- Нет режима совместного участия нескольких людей в split одновременно.
- Нет постоянных групп, истории и повторного использования состава участников.
- Нет режима "кто уже оплатил / кто перевел".
- Нет ссылок на оплату и автоматического settlement.
- Нет web view / mini app для наглядного подтверждения долей.
- Нет мультивалютности и сценариев поездок.
- Нет экспорта в PDF/Excel/CSV.
- Нет личной памяти: кто обычно ест что, как делятся чаевые, любимые составы групп.
- Нет явного механизма ручной правки OCR прямо в удобном интерфейсе.

## Что добавить, чтобы реально выйти вперед

### 1. Collaborative claim mode

После распознавания бот создает ссылку или QR. Каждый участник открывает mini web view и сам отмечает свои позиции.

Почему это сильно:

- убирает одного "оператора" чека;
- снижает ошибки и споры;
- превращает split в совместное действие за 30-60 секунд.

### 2. Smart ambiguity resolver

Если OCR не уверен или есть одинаковые позиции, бот задает микро-вопросы:

- "Кто брал 2 капучино?"
- "Этот стейк делить на двоих или на одного?"

Это даст реальное product moat, потому что большинство конкурентов просто парсят чек и оставляют пользователю ручную уборку ошибок.

### 3. Auto-settlement links

Сразу после split:

- показать кто кому должен;
- сгенерировать готовые суммы для перевода;
- дать кнопки: `Оплатил`, `Напомнить`, `Поделиться`.

Следующий шаг: интеграции с локальными платежами и deep links банков.

### 4. Group memory

Запоминать:

- постоянные компании;
- любимые шаблоны split;
- чаевые по умолчанию;
- кто обычно не пьет алкоголь;
- семейные пары как единый плательщик;
- частые рестораны и типичные ошибки OCR по ним.

Это резко ускорит повторные сценарии и сделает продукт умнее конкурентов со временем.

### 5. Multi-receipt merge

Объединять:

- основной чек;
- барный чек;
- десерты позже;
- чаевые отдельно;
- несколько фото длинного чека.

Для ресторанов и поездок это очень практично и хорошо отличает продукт от "один чек - один split".

### 6. Explainable split

Не просто итог, а прозрачное объяснение:

- блюда;
- доля сервисного сбора;
- доля чаевых;
- корректировки;
- округление.

Это уменьшает недоверие и споры.

## Самая сильная продуктовая ставка

Если выбирать одну фичу, которая способна выделить PayTogether сильнее всего, я бы ставил на связку:

`AI receipt split + совместное подтверждение позиций участниками + мгновенное settlement после чека`

Это лучше отвечает реальному ресторанному моменту, чем классические expense trackers, которые чаще сильны "после события", а не "в момент оплаты".

## Рекомендованный roadmap

### Этап 1

- Сохранение постоянных групп и шаблонов участников
- Ручная правка OCR-позиций
- Экспорт итогов
- Статусы `оплатил / не оплатил`

### Этап 2

- Collaborative claim mode через ссылку / Telegram Mini App
- Напоминания о долгах
- История чеков и повторные сплиты
- Multi-receipt merge

### Этап 3

- Платежные deep links
- Персональная group memory
- Рекомендации по распределению на основе прошлых чеков
- Аналитика по ресторанам, тратам и участникам
